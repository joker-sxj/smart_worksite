# 阶段四：Excel/PPT 原生内容解析与知识库入库设计

## 1. 目标与范围

本阶段完善现有 Java + Apache POI 文件解析链路，实现 Excel、CSV 和 PowerPoint 原生内容从上传到知识库问答的生产闭环：

```text
文件上传 -> 异步解析 -> 解析结果与定位信息 -> 入库校验 -> 切片/Embedding/向量入库 -> 问答引用
```

支持 `.xls`、`.xlsx`、`.csv`、`.ppt`、`.pptx`。处理单元格、多个 Sheet、表头、行列、日期、数字、合并单元格、幻灯片标题、文本框、表格、可稳定读取的备注以及来源定位。

本阶段不识别 Excel/PPT 内嵌图片、扫描件、图表、SmartArt 中的视觉文字，不调用视觉模型。包含原生文本和图片时解析原生文本并标记未识别图片；仅包含图片时必须失败并显示“未发现可解析文本，需使用 OCR”，不得生成空知识库内容。

## 2. 已有架构与约束

沿用并完善现有边界：

- `DocumentParserRegistry` 按扩展名和 Content-Type 选择解析器。
- `ExcelDocumentParser` 解析 Excel/CSV。
- `PowerPointDocumentParser` 解析 PPT/PPTX。
- `PreparedDocument` 统一承载文本、结构化 Block、页数和截断信息。
- `FileParseWorker` 负责任务执行、状态和解析结果对象保存。
- `KnowledgeBaseApplicationService` 校验解析结果身份并提交向量入库。
- Vue 知识库页面显示解析/入库状态、详情和操作。

解析、入库是两个独立状态机，错误原因不得用笼统 `Failed` 代替。所有调用使用本地服务；实机验收使用真实文件、真实 MinIO、MySQL、本地 Embedding、Reranker 和 LLM，不以 Mock 结果作为验收结论。

## 3. 统一结构化 Block

每个进入知识库的 Block 必须包含可读正文和可追溯位置。现有 `PreparedDocument` Block 协议继续作为唯一边界，补齐以下语义：

- Excel/CSV：`sourceType=EXCEL_ROW` 或 `CSV_ROW`，包含 `sheetName`、`rowStart`、`rowEnd`、`columnStart`、`columnEnd`。
- PPT：`sourceType=PPT_TEXT`、`PPT_TABLE` 或 `PPT_NOTES`，包含 `slideNumber`。
- 文件级元数据包含格式、Sheet/幻灯片数量、Block 数量、是否截断、是否发现未识别图片。

Excel 行应把表头和数据组合为可检索文本，例如：

```text
日期：2026-08-01；区域：1号塔楼；风险等级：中风险；问题：临边防护缺口
```

引用展示至少能还原“文件名 + Sheet/行”或“文件名 + 幻灯片页码”。后续图片 OCR 只需增加新 `sourceType`，不改变本阶段协议。

## 4. 格式规则

### 4.1 Excel

- 按工作簿和 Sheet 顺序读取，跳过完全空白行列。
- 保留 Sheet 名、原始行号和有效列范围。
- 使用格式化显示值，日期可读、数字不意外转科学计数法、公式优先使用缓存计算值并保留可诊断失败。
- 首个有效行作为表头候选；数据行与表头组合，表头重复或缺失时使用列标识稳定退化。
- 合并单元格只输出一次，避免重复膨胀。
- 检测图片存在但不提取图片文字。
- 工作簿无任何有效文本时返回可操作的无文本错误。

### 4.2 CSV

- 支持 UTF-8、UTF-8 BOM 和常见中文编码的受控探测。
- 支持逗号和制表符等常见分隔符，保留行号和列范围。
- 第一有效行作为表头候选；异常列数必须给出明确警告或失败原因。
- 仅有表头可形成解析结果，但元数据标记无业务数据行，问答不得虚构数据。
- 空文件失败。

### 4.3 PowerPoint

- 按幻灯片顺序读取标题、普通文本框、表格及可稳定读取的备注。
- 每个 Block 保留幻灯片页码和内容类型。
- 检测图片、图表、SmartArt 的存在并写入文件级元数据，但不识别其中视觉文字。
- 无任何原生文本时返回“未发现可解析文本，需使用 OCR”。

## 5. 状态与一致性

解析状态沿用 `PENDING -> RUNNING -> SUCCESS`，异常为 `FAILED`/`CANCELED`，失败记录可重试。`SUCCESS` 必须同时满足：文件可打开、解析器完成、存在有效正文/Block、结果对象已写入、元数据可序列化、项目/文件/文档身份一致。

入库状态沿用 `PENDING -> INDEXING -> SUCCESS`，失败为 `FAILED` 并可重新入库。仅在以下条件成立时允许提交：

- 最新解析记录为 `SUCCESS`；
- 结果对象存在且正文非空；
- 解析元数据中的项目、文件、文档身份与当前对象一致；
- 文档和知识库未删除且知识库启用；
- 用户具备当前项目管理权限；
- 没有正在执行的解析或入库任务。

旧解析任务不得覆盖更新的解析结果；前端持有的旧状态不能绕过后端校验。解析失败、无文本、跨项目、结果对象丢失必须在入库前失败并返回具体原因。

## 6. 前端交互

知识库列表分别展示解析状态、入库状态和说明：

- 未解析：可“解析文件”。
- 解析中：按钮禁用，刷新后从服务端恢复状态。
- 解析成功：可查看结果详情和入库。
- 解析失败/无文本：显示明确原因，可重新解析，禁止入库。
- 入库中：按钮禁用并轮询。
- 入库成功：显示成功且不重复提交。
- 入库失败：显示具体原因并允许重试。

详情至少显示文件信息、解析器、状态、耗时、摘要、Sheet/幻灯片数量、Block 数、截断状态、是否包含未识别图片、解析错误、入库状态和入库错误。前端不得用本地临时状态覆盖服务端最终状态。

## 7. 问答与引用

入库后必须验证：

- Excel/CSV 中的日期、区域、负责人、风险等级、整改状态、统计和筛选问题。
- PPT 中指定页、标题、文本框、表格、跨页总结问题。
- 引用显示文件名及 Sheet/行或幻灯片页码。
- 仅使用指定文档时不混入其他来源。
- 无证据、仅表头、图片文字未解析、空数据库等边界不得编造。

## 8. 错误处理与安全

必须区分并持久化：格式不支持、扩展名/内容不匹配、文件损坏、加密文件、超限、无文本、结果对象存储失败、元数据失败、Embedding/向量入库失败、跨项目身份不一致和任务冲突。

错误可供用户行动但不得泄露堆栈、对象存储永久地址、密码、Token、完整文档正文、图片 Base64 或敏感字段。不可重试错误受控失败，不允许无限重试。

## 9. 测试与验收

自动化测试覆盖 `.xls/.xlsx/.csv/.ppt/.pptx` 正常解析、多 Sheet、多页、合并单元格、日期/数字/布尔值、PPT 表格、备注、图片标记、空文件、损坏文件、仅图片、超限、元数据序列化、项目身份、旧任务覆盖、解析入库门禁和前端刷新/按钮/错误详情。

Chrome 实机使用真实文件完成不少于 30 个场景，至少覆盖：五种扩展名、成功和失败、多 Sheet、多页、合并单元格、日期数字、PPT 表格、原生文本加图片、仅图片、空文件、损坏文件、重复上传、刷新恢复、失败重试、解析后入库、入库重试、Excel/PPT 问答引用、无证据和跨项目隔离。

分别统计任务完成和业务正确。每个独立问答场景新建会话。验收后检查 Java、Python、本地 LLM、Embedding、Reranker、MySQL、Redis、MinIO、前端和容器日志；不得遗留新 422、5xx、超时、OOM、CUDA 错误、容器重启、无限重试或敏感泄露。
