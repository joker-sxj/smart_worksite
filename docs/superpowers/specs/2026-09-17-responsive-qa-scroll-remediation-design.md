# 响应式问答滚动与抽屉导航修复设计

## 1. 背景与证据

2026-09-16 在真实部署页面 `http://172.18.12.6:5173/qa` 完成桌面和 `390x844` 浏览器实测。

桌面端行为符合预期：进入和切换长会话后定位最新回答，提交问题后跟随生成状态；用户向上阅读时，新回答到达后保持原位置并显示“有新回答，回到底部”，点击后回到底部。

窄屏端暴露两个确定问题：

1. 用户向上滚动后，新回答首次到达时位置能够保持并显示返回按钮，但后续异步刷新仍可能自行滚到底部，返回按钮随之消失。
2. `MainLayout` 的固定 `236px` 侧栏在 `390px` 视口下不折叠，正文被压缩为极窄列并产生横向滚动。

本设计只根据上述可复现证据定义修复，不把 H100 功能环境外推为客户双 A6000 性能验收，也不把其他业务页面已有桌面验收外推为全站移动端业务组件验收。

## 2. 目标

1. 连续轮询、发送完成和异步渲染都不能覆盖用户“正在阅读历史”的明确意图。
2. 首次进入、切换会话和主动提交问题仍应定位最新消息。
3. `960px` 以下使用 A 方案：隐藏固定侧栏，通过顶栏按钮打开抽屉导航。
4. 在 `390x844` 下消除全局外壳造成的横向溢出，让问答的会话列表、正文、输入框和主要操作可阅读、可点击。
5. 保持桌面布局和既有路由、权限、项目切换行为兼容。

## 3. 非目标与边界

- 不在本任务中重新设计每个业务页面的表格、图表和复杂表单移动布局。
- 不改变后端问答接口、轮询间隔、消息状态或数据库结构。
- 不处理成功知识文档强制重建索引、旧文档清理、PostgreSQL/Kingbase 实库验收、A6000 性能验收或凭据轮换。
- 不删除本轮浏览器验收产生的普通问答消息；它们不含敏感信息。
- 不将普通 PDF 动态报告模板、robots 受限来源改为支持范围。

## 4. 滚动意图模型

### 4.1 状态

问答页维护显式的跟随意图，而不是在每次异步刷新时仅根据瞬时 DOM 高度重新推断：

- `FOLLOWING_LATEST`：允许轮询和回答渲染继续跟随底部。
- `READING_HISTORY`：禁止任何非用户强制操作滚到底部，并显示返回按钮。

初始状态为 `FOLLOWING_LATEST`。

### 4.2 状态转换

| 事件 | 新状态 | 页面动作 |
|---|---|---|
| 首次加载完成 | `FOLLOWING_LATEST` | 强制定位最新消息 |
| 切换会话 | `FOLLOWING_LATEST` | 强制定位新会话最新消息 |
| 用户主动提交问题 | `FOLLOWING_LATEST` | 定位用户消息和生成状态 |
| 用户在活动滚动容器中离开底部阈值 | `READING_HISTORY` | 保持位置 |
| 轮询或发送完成，且状态为 `FOLLOWING_LATEST` | 不变 | 跟随最新内容 |
| 轮询或发送完成，且状态为 `READING_HISTORY` | 不变 | 不滚动，显示返回按钮 |
| 用户滚动回底部阈值内 | `FOLLOWING_LATEST` | 隐藏返回按钮 |
| 用户点击“回到底部” | `FOLLOWING_LATEST` | 强制定位底部并隐藏按钮 |

程序触发的滚动会用短生命周期保护标记与用户滚动区分，避免 `scrollIntoView` 产生的 `scroll` 事件错误修改意图。

### 4.3 活动滚动容器

- 桌面端：`.message-scroll`。
- 响应式端：最近的 `MainLayout .content`。
- 页面挂载、断点变化或 DOM 更新后，解析活动滚动容器；事件监听不得永久绑定到已失效的容器。
- `READING_HISTORY` 的判断基于当前活动容器及统一底部阈值，不依赖窗口滚动对象。

### 4.4 竞态处理

`poll` 与 `send-complete` 不再接收一次性的 `wasNearBottom` 作为最终决定，而是读取持久意图。即使消息高度在两次异步操作之间变化，只要用户没有主动回到底部或发起强制跟随事件，状态就保持 `READING_HISTORY`。

会话切换采用会话级重置；旧会话迟到响应仍由既有 session/token 校验丢弃，不得改变新会话的滚动意图。

## 5. A 方案响应式外壳

### 5.1 断点和导航

- `min-width: 961px`：保持现有 `236px` 固定侧栏。
- `max-width: 960px`：隐藏固定侧栏，在顶栏显示具有可访问名称的菜单按钮。
- 菜单按钮打开 Element Plus 抽屉；抽屉宽度为 `min(320px, 88vw)`，复用现有品牌和权限过滤后的导航菜单。
- 路由成功切换后自动关闭抽屉；关闭抽屉不改变当前项目或会话。

### 5.2 顶栏

- 窄屏顶栏允许换行，不保持桌面固定单行布局。
- 第一行包含菜单按钮、项目简称和必要的用户入口。
- 项目选择器占可用宽度，不使用桌面固定 `240px` 宽度。
- “去提问”在当前已经位于问答页面时可隐藏或降级，避免挤占空间；其他页面仍保留问答入口。

### 5.3 内容区域

- `.main-shell`、`.topbar`、`.content` 和问答页直接子项设置正确的 `min-width: 0`。
- 窄屏内容内边距缩小，但保留触控间距。
- 全局外壳不得产生页面级横向滚动；确实需要横向展示的业务表格由各自局部容器负责。
- 问答页保持单列顺序：会话列表、对话区；不把固定侧栏或抽屉宽度计入正文宽度。

## 6. 组件与文件边界

### `frontend/src/views/qa/qaMessageScroll.ts`

承载纯滚动意图状态转换和底部判定，不访问 DOM。测试连续事件序列，而不仅测试一次 `wasNearBottom`。

### `frontend/src/views/qa/QaView.vue`

负责解析活动滚动容器、绑定/解绑监听、区分程序滚动与用户滚动，并在轮询、发送完成、会话切换和返回按钮中调用纯策略。

### `frontend/src/layouts/MainLayout.vue`

负责桌面侧栏、窄屏抽屉、顶栏重排和全局横向溢出控制。菜单定义保持单一来源，桌面侧栏和抽屉复用同一数据。

### 测试文件

- `frontend/src/views/qa/qaMessageScroll.spec.ts`：状态机和连续轮询竞态。
- `frontend/src/views/qa/QaView.spec.ts`：页面接线、活动容器和按钮行为合同。
- `frontend/src/layouts/MainLayout.spec.ts`：抽屉导航、断点类名、路由后关闭和项目选择器合同。

不为测试向生产组件添加无业务意义的公开方法。

## 7. 错误处理与兼容性

- 抽屉打开/关闭不触发网络调用。
- 项目加载失败、用户信息缺失和权限过滤继续沿用现有处理，不引入新的静默回退。
- 若活动滚动容器暂时不存在，策略不执行滚动；DOM 就绪后由强制事件重新定位，不能回退到猜测 `window`。
- 尊重 `prefers-reduced-motion`；本任务不要求动画滚动，使用确定性即时定位。
- 桌面现有导航结构、默认展开分组和路由地址保持不变。

## 8. 测试与验收

### 8.1 TDD 自动化

先增加能够复现以下行为的失败测试：

1. 用户离开底部后，连续两次 `poll` 和一次 `send-complete` 都保持 `READING_HISTORY`。
2. 消息高度变化不能自行解除 `READING_HISTORY`。
3. 点击返回按钮、切换会话和提交问题分别恢复 `FOLLOWING_LATEST`。
4. `390px` 断点显示菜单按钮和抽屉，隐藏固定侧栏。
5. 抽屉路由选择后关闭，导航权限过滤与桌面一致。
6. 窄屏顶栏和内容不依赖固定 `236px + 240px` 宽度。

定向测试必须先因缺少行为而失败，再以最小实现转绿。随后运行全部前端测试和生产构建。

### 8.2 真实浏览器

部署精确提交后，在同一真实项目和长会话中验证：

- 桌面进入会话、切换会话、提交、向上阅读、连续轮询和返回按钮。
- `390x844` 下抽屉开关、导航跳转、项目选择、会话切换、提交、向上阅读、至少两次轮询和返回按钮。
- 窄屏截图中正文不再逐字换行，无全局横向滚动。
- 浏览器控制台没有由本次修改引入的 error/warn。

实机只有在新回答终态到达后继续等待至少一个额外轮询周期、滚动位置仍不变化，才能判定竞态关闭。
