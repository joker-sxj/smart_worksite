# 文件解析状态展示设计

日期：2026-08-04

## 背景

文件解析任务由后端异步执行。前端提交任务后只刷新一次解析记录，此时记录通常仍为 `PENDING`，后续即使后端已经进入 `RUNNING` 或完成，页面也不会自动更新，用户容易误认为解析卡住。

## 目标

在文件解析相关界面准确展示异步任务状态，不展示百分比或耗时：

- `PENDING`：待处理
- `RUNNING`：解析中
- `SUCCESS`：解析成功
- `FAILED`：解析失败

## 设计

### 状态文案

文件解析页面使用上下文专属的状态文案，不修改通用 `StatusTag` 对 `RUNNING` 的全局翻译，避免任务中心、报告生成等模块被错误显示为“解析中”。

### 自动刷新

当当前文件存在 `PENDING` 或 `RUNNING` 的解析记录时，前端每 2 秒重新请求解析记录。所有记录进入终态后停止轮询。切换文件或卸载页面时清理定时器，避免重复请求和资源泄漏。

### 操作反馈

提交解析或重试后立即刷新记录并启动轮询。任务完成后显示“解析成功”；任务失败后显示“解析失败”，保留错误原因和重试入口。

## 边界与约束

- 不新增 WebSocket 或 SSE。
- 不修改后端状态枚举和接口协议。
- 不使用仅存在于浏览器内存的虚假“解析中”状态。
- 同一页面只维护一个轮询定时器。
- 请求失败时保留现有记录并停止当前轮询，向用户展示加载错误，避免无限失败请求。

## 验收标准

1. 新建解析任务后，页面可从“待处理”自动更新为“解析中”。
2. 后端任务完成后，页面自动更新为“解析成功”或“解析失败”。
3. 不需要用户手动刷新页面或重新选择文件。
4. 离开页面或切换文件后，不再轮询旧文件。
5. 任务中心等非解析页面的 `RUNNING` 文案保持不变。
6. 前端单元测试覆盖状态文案、轮询启动和轮询停止条件。
