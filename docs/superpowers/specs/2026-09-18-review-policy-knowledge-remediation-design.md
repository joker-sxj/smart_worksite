# 合规审查 政策资讯与知识库列表修复设计

## 背景与结论

2026 年 9 月 18 日的真实部署数据和用户截图确认了三个相互独立的问题：合规审查结果已经持久化，但页面只能通过浏览器本地记录定位结果，并且只把顶层 `issues` 当作问题；政策资讯页面没有区分来源发布日期与系统抓取时间，单篇文章地址也没有说明无法发现后续文章；知识库后端已经支持分页，前端却只读取默认第一页且没有分页控件。

本次修复复用现有后端审查记录列表、政策文章时间字段和知识文档分页接口。不会把抓取时间写入来源发布日期，也不会把缺少问题明细的不确定模型结论伪装成普通问题。

## 范围

### 合规审查

- 页面进入或切换项目后，从服务端查询该项目最近的审查记录。
- 浏览器保存的最后查看记录仍有效时优先恢复；缺失、无权访问或已经删除时，回退到服务端最新记录。
- 非终态记录恢复后继续轮询；终态记录直接展示，离开页面不影响后端任务执行。
- 页面提供最近审查记录选择入口，用户可以重新打开已有结果。
- 顶层 `issues` 继续作为可处理的“明确问题”，保留状态修改能力。
- `ruleResults` 中需要人工确认、执行失败或包含 `validationError` 且没有形成明确问题的项目，展示在独立的“待人工确认”区域。
- 待人工确认项展示规则编号、规则名称、模型判定、置信度、原因和证据摘要；不生成虚假的 `issueId`，不允许通过问题状态接口修改。
- 原始 JSON 继续保留为技术审计信息。
- 页面明确提示处理中任务可离开，返回后会从服务端恢复并继续刷新。

### 政策资讯

- `publishDate` 保持来源网站的文章发布日期。
- `createdAt` 表示首次入库时间，`updatedAt` 表示该文章记录最近一次成功抓取或更新的时间。
- 列表至少展示“发布日期”和“最近抓取”；详情同时展示发布日期、首次入库和最近抓取。
- 新增或编辑来源时识别明显的单篇文章 URL，并提示该地址只能刷新当前文章，不能发现同栏目的后续文章。
- 单篇文章 URL 仍允许保存和抓取，因为固定内容刷新是有效场景。
- 栏目抓取先收集并去重候选链接，再在数量上限前优先选择 URL 路径中可可靠解析出 `YYYYMMDD` 日期的较新链接；日期相同或无法解析时保持网页原始顺序。
- 同一规范化 URL 继续更新原文章，新 URL 新增文章；不创建重复历史快照。
- robots.txt 和反爬限制保持现有合规策略，不增加绕过逻辑。

### 项目知识库文档

- 复用现有 `pageNo`、`pageSize`、`keyword`、`indexStatus` 和 `total` 接口契约实现服务端分页。
- 页面保存当前页、每页数量、总数、文件名关键字和入库状态筛选。
- 切换知识库、改变关键字或状态筛选时回到第一页。
- 上传成功后回到第一页并刷新；删除后刷新当前页，当前页因删除变空且不是第一页时回退一页。
- 解析和入库自动刷新只刷新当前查询页，不重置用户页码和筛选条件。
- 解析记录查询范围只覆盖当前页文档，避免文档数量增加后产生无界请求。

## 组件边界

### 前端视图模型

合规审查新增纯函数，负责从记录列表选择恢复目标，以及从 `ruleResults` 派生待人工确认项。函数不访问网络和浏览器存储，便于对本地记录有效、无效和规则结果异常等情况做确定性测试。

政策资讯新增纯函数，判断 URL 更像栏目还是单篇文章，并负责时间展示的空值处理。该判断只用于用户提示，不作为禁止保存的安全门禁。

知识库页面使用独立分页状态构造查询参数；所有加载、刷新、上传和删除路径经过同一个 `loadDocs` 方法，避免某些路径遗漏分页参数。

### 后端与爬虫

审查和知识库后端接口保持兼容，不新增数据库迁移。政策 Python 爬虫新增候选链接排序逻辑，输入输出数据结构保持不变。

## 数据流

### 审查恢复

1. 获取当前项目。
2. 并行或顺序加载模板、参考文档和最近审查记录。
3. 如果本地记录 ID 存在于服务端结果中，选中该记录；否则选中服务端第一条最新记录。
4. 获取完整记录及任务阶段日志。
5. 非终态记录继续轮询，终态记录停止轮询。

### 政策重复抓取

1. 每次任务重新读取来源地址和 robots.txt。
2. 栏目页收集候选链接，并按可解析日期降序、原始顺序升序选择上限内链接。
3. 单篇页没有子文章候选时，保存该页本身。
4. Java 按规范化 URL 哈希更新或新增文章。
5. 页面分别显示来源发布日期和系统时间。

### 知识库分页

1. 页面使用当前知识库 ID、页码、页容量和筛选条件请求服务端。
2. 服务端返回当前页记录与总数。
3. 页面只为当前页可解析文档查询解析状态。
4. 自动刷新保留同一查询条件。

## 错误处理

- 合规审查列表加载失败时显示可见错误，但不清除已经成功加载的当前记录。
- 本地记录无法加载时清除该项目对应的无效本地记录，并回退服务端最新记录。
- 服务端没有审查记录时展示正常空状态，不启动轮询。
- 政策时间为空时显示“未提取”或“-”，不使用当前时间填充。
- 政策链接没有可解析日期时保持来源顺序，避免凭标题猜日期。
- 知识库请求失败时保留分页条件，显示错误并停止该轮自动刷新；用户可重试。

## 非目标与限制

- 本次不重新设计模型审查规则或补造模型未返回的问题描述。
- 本次不建立政策文章版本历史。
- 本次不保证任意网站都能可靠提取发布日期；来源没有明确日期时允许显示未提取。
- 本次不绕过 robots.txt、登录限制或第三方反爬机制。
- H100 环境只能证明功能链路，不能替代客户双 A6000 性能验收。
