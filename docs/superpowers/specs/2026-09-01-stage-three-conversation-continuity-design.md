# 第三阶段：多轮上下文与延伸问题设计

## 目标与范围

本阶段解决现场需求“智能问答上下文关联，并像豆包一样在回答下方自动展示可继续提问的延伸问题”。实现会话级结构化摘要、最近消息、上下文独立问题改写、每轮动态检索和最多 3 个延伸问题。点击延伸问题后，它立即作为当前用户的新消息发送并生成下一轮回答。

本阶段不实现跨会话用户画像或永久个人记忆。所有模型调用继续受 `LOCAL_ONLY` 门禁约束，并复用现有上下文预算、动态检索、任务状态、引用和权限机制。

## 交互约定

- 主答案完成后自动显示延伸问题，不需要点击展开。
- 延伸问题生成不阻塞主答案；生成失败不把主答案改为失败。
- 最多显示 3 条；无合格问题时不显示空区域。
- 点击后立即保存为正常用户消息并发送，不经过二次确认。
- 点击期间锁定延伸问题，客户端提交锁和服务端幂等键共同防止双击重复消息。
- 原答案和原延伸问题保留；已点击项显示为已提问。
- 页面刷新后恢复延伸问题，新建会话和切换项目后不继承旧内容。

## 数据流

```text
用户输入或点击延伸问题
-> Java 校验 userId/projectId/sessionId、知识库和数据源
-> 读取结构化摘要与预算允许的最近消息
-> Python 将指代型追问改写为独立问题
-> 使用独立问题执行动态检索或数据库查询
-> 本地模型基于当前证据生成答案
-> 保存助手消息和引用并立即向前端可见
-> 本地模型生成结构化延伸问题
-> 过滤、去重、持久化，前端轮询后自动展示
-> 达到阈值时异步更新结构化会话摘要
```

改写只能补充当前会话已确认的标准、地区、时间、对象和主题，不能创造新条件。改写失败时使用原问题继续，不进行无界重试。每一轮仍重新检索和重新校验资源，不把摘要或上一轮结果当成事实源。

## 会话记忆

新增独立会话记忆记录，绑定 `userId + projectId + sessionId`，保存摘要 JSON、覆盖到的最后消息 ID、版本、估算 Token、状态和更新时间。摘要结构包含：

- `topics`：当前主题；
- `standards`：涉及的标准、政策和文档；
- `constraints`：地区、时间和对象；
- `confirmedFacts`：已由证据确认的事实；
- `userCorrections`：用户最新纠正；
- `openQuestions`：未解决问题。

用户最新纠正优先于旧摘要。摘要不保存完整 Prompt、密码、连接串、Token、未脱敏异常、其他项目消息或无权限资料正文。摘要损坏时丢弃并安全重建；摘要失败时回退最近消息，不能影响主回答。

## 上下文预算

上下文保留优先级依次为：系统安全与证据约束、当前问题、当前证据、最近消息、结构化摘要、较旧可选历史。不能为了保留旧历史截断当前问题、关键证据或输出预留。达到消息数或 Token 阈值后更新摘要，同一会话只允许一个摘要更新任务。

## 延伸问题

本地模型接收当前问题、答案摘要、实际入模证据要点、当前路由和未解决问题，返回严格 JSON 数组。服务端最多保留 3 条，并过滤空白、编号前缀、超长问题、当前问题、历史已回答问题、重复或明显同义问题、无关内容、跨项目信息和危险写操作。

证据不足时优先生成补充地区、时间、对象、标准名称或资料范围的问题。DATABASE 和 MIXED 同样支持延伸问题，但点击后必须重新查询数据库并重新校验数据源，不复用旧查询结果冒充最新结果。

延伸问题状态为 `PENDING`、`SUCCESS`、`EMPTY` 或 `FAILED`。生成最多尝试一次；失败不触发主答案重试。

## API 与持久化

- 助手消息增加延伸问题 JSON 和生成状态；历史消息 API 原样返回。
- 用户消息可携带可选幂等键和来源延伸问题 ID；普通文本发送保持兼容。
- 问答响应继续返回原问题，另返回独立检索问题的安全诊断，不泄漏内部 Prompt。
- 会话删除或归档遵循现有生命周期；记忆数据与会话一起不可再用于新请求。
- 数据迁移兼容历史消息，新增字段允许为空。

## 权限与安全

每次发送、异步执行、摘要更新和延伸问题生成都重新校验项目、会话、知识库和数据源。撤权或资源禁用后任务受控取消，不进入无限重试。缓存键必须包含项目和会话维度；跨项目 sessionId、知识库 ID 或数据源 ID 返回受控错误且不暴露资源详情。

## 异常边界

- 上下文改写最多一次，失败回退原问题。
- 动态检索继续最多两轮。
- 延伸问题生成最多一次，失败时主回答保持成功。
- 摘要更新有限重试且不阻塞回答。
- 页面刷新不能重复创建回答、摘要或延伸问题任务。
- 所有错误信息脱敏，不保存内部 URL、路径、Token、连接串、Prompt 或完整证据正文。

## 验收

遵循 `docs/superpowers/runbooks/real-machine-acceptance-process.md`。自动化必须覆盖摘要结构、用户纠正、预算、指代改写失败回退、延伸问题格式/过滤/去重、幂等点击、历史恢复、权限撤销和资源禁用。

真实 Chrome 验收不少于 40 个问题且不设上限，覆盖直接追问、指代、纠正、主题切换、长会话摘要、数据库连续追问、MIXED 连续追问、刷新恢复、新建会话隔离、跨项目隔离、自动展示、点击立即发送、防双击、无证据、部分证据、超时和资源禁用。每个独立场景先新建会话。

阶段完成前必须检查 Java、Python、本地模型、Embedding、Reranker、数据库和容器日志；所有本次新增异常必须处理。自动化、实机、日志和远端提交校验全部通过后，才允许推送 `joker-sxj/smart_worksite:main`。
