# 第七阶段生产级报告图表修复设计

日期：2026-09-11

## 1. 问题与目标

报告“第七阶段PDF实机验收-0905”中的图表是系统正式生成的 PNG，不是待生成占位图。根因是现有流程把数据库返回的任意文本列全部统计，并直接选择第一组分类绘图；单分类柱宽又接近整个绘图区。同时，图中没有标题、维度、分类标签、刻度、数值、单位和来源。因此当前实现只证明“可以生成并嵌入图片”，不满足生产级业务表达。

本次目标是建立从业务数据资格、图表规格到可读渲染的通用链路，保证图表选对数据、表达完整，并在无有效业务数据时明确不绘图。

## 2. 数据资格与字段治理

报告表格保留数据库查询返回的白名单列，但绘图候选字段执行二次治理：

- 排除 ID、任务、模板、报告、变量、生成状态、创建更新时间等技术字段。
- 排除全空、占位值、只有空白和没有业务含义的字段。
- 优先识别风险等级、整改状态、负责人、区域、隐患类型、日期和时间字段。
- 唯一标识、高基数字段和无可识别业务维度不绘图。
- 无有效业务数据时输出“未生成图表”的明确说明，不把一条技术记录解释成一项业务风险。

字段识别采用通用关键词和统计特征，不针对报告名称或 `var_risk` 写特殊分支。

## 3. 图表规格

新增独立的图表规划结果，至少包含：标题、类型、维度、单位、分类值、数据来源和不绘制原因。业务统计与绘图实现解耦：规划器负责选择正确维度，渲染器只负责按规格绘制。

- 风险等级、整改状态、隐患类型、区域、负责人：条形图。
- 日期或月份：折线图。
- 分类过多：保留前十项并合并其他。
- 单分类：固定合理柱宽并居中。
- 无合格字段：不产生 PNG。

## 4. 可读性标准

图表必须展示中文标题、维度/单位、分类标签、数值、纵轴刻度和数据来源。长标签进行省略或换行，坐标与文字不得重叠。服务器优先使用 Noto Sans CJK SC，缺失时回退到可用中文字体。

正文表格不再让技术元数据驱动图表；本次不重构数据库查询结果本身，避免扩大范围。后续可单独设计“技术依据附录”。

## 5. 错误处理

- 无业务数据属于正常不可绘制状态，不记录为生成故障。
- 字体或图片编码失败时写入可诊断日志，并在报告中显示未绘制原因，不静默吞掉异常。
- 图表错误不得阻断 Word/PDF 主报告生成，但不能伪装成图表成功。

## 6. 验收

自动化覆盖多风险等级、单分类、多负责人、月份趋势、长中文标签、分类上限、全空值、占位值、只有技术字段、图表数值与统计一致以及 PNG 标签可验证性。

实机使用真实 MySQL 数据构造或选取授权业务记录，至少生成风险等级、负责人或状态分布之一，并验证：Chrome 任务完成；Word/PDF 图表清晰；标题、标签、数值、单位、来源齐全；表格、图表和结论数字一致；空数据报告不生成误导图；Java、Python、本地模型、LibreOffice、MySQL/Redis/MinIO 和浏览器日志无本轮异常。

原第七阶段报告结论更新为：文件导出链路已通过；旧图表业务可读性不通过；以本次修复后的实机报告作为图表能力关闭证据。
