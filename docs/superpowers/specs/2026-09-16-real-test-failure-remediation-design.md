# 真实文件测试失败修复设计

## 目标

修复 2026-09-16 真实测试中确认的三个缺陷：旧版 XLS 区域日期显示为序列值、进入或切换问答会话时没有定位到最新消息、合规审查因重复规则编号而写入失败。修复后在真实 H100 功能环境回归，但不把该结果外推为客户双 A6000 性能结论。

## 已核实事实

### 旧版 XLS 日期

- 输入文件 `7月中旬进度计划.xls` 是旧版 BIFF 工作簿。
- Excel 将 D4 的原始数值 `37089` 显示为 `7月17日`，完整日期为 `2001-07-17`。
- Apache POI 读取该单元格时得到格式编号 `58`，但格式字符串为 `null`，因此现有 `DataFormatter` 输出 `37089.0`。
- 文件同时包含 2001 年与 2007 年日期。系统不得根据文件名、上传时间或当前年份猜测年份。
- 当前知识库资料 `sourceId=519` 已包含错误解析结果；部署代码后必须重新解析并重新索引。

### 问答会话滚动

- `QaView.vue` 的消息区是独立滚动容器。
- 首次加载、切换会话、发送完成和轮询刷新都会替换消息数组，但没有显式滚动逻辑。
- 用户需求是进入已有会话时看到最近一次回答，同时在主动查看历史时不被轮询强制拉回底部。

### 合规审查重复规则

- 真实记录 119 在保存第二个 `RULE-004` 时触发唯一键冲突。
- 数据库已留下 `RULE-001` 至第一个 `RULE-004` 的部分结果，说明当前异步写入不是原子的。
- 规则解析器仅以展示编号生成持久化 ID；重复编号或 PDF 重复文本层会产生相同 ID。
- 待审查文件 `测试合规文档.docx` 可以正常读取，失败发生在 AI 审查后的结果持久化阶段。

## 设计

### 1. 日期解析与索引内容

新增专门的电子表格单元格值格式化边界，普通文本、数字、布尔值和公式继续沿用 POI 显示值。对日期采用以下顺序：

1. POI 能识别的日期格式，读取完整日期并保留原显示文本。
2. HSSF 中格式字符串缺失但格式编号属于区域性日期内建编号时，将数值按工作簿的 1900/1904 日期系统转换。
3. RAG 文本统一写成 `yyyy-MM-dd（原表显示：M月d日）`；若原格式本身已经显示完整年份，避免重复附注。
4. 结构化数据同时保留单元格地址、原始数值、标准日期、显示值和格式编号，便于审计。

只在有可靠样式证据时执行日期转换，普通数值 `37089` 不得被猜成日期。公式日期使用缓存结果和同样的样式判定。

### 2. 会话最新消息定位

将滚动策略抽成可测试的纯函数：判断用户是否处于底部阈值内，以及计算是否需要自动跟随。页面行为如下：

- 首次进入已有会话和切换会话：Vue 完成 DOM 更新后强制滚动到底部。
- 本地提交新问题：追加用户消息和生成占位后滚动到底部。
- 发送完成或轮询刷新：仅当刷新前位于底部附近时继续跟随。
- 用户向上查看历史：保持位置，并显示“有新回答，回到底部”按钮。
- 新空会话不执行无意义滚动；移动端使用当前页面滚动模型，不引入第二套消息容器。

底部阈值采用小范围像素容差，避免字体渲染和小数滚动高度导致误判。

### 3. 审查规则身份与原子写入

展示编号和内部唯一 ID 分离。规则仍保留原编号和标题供用户查看；内部 ID 在同一模板解析结果内稳定去重：第一次编号 4 使用 `RULE-004`，随后依次使用 `RULE-004-2`、`RULE-004-3`。生成顺序完全由解析顺序决定，不依赖模型输出。

模型调用前校验规则 ID 唯一，防止消耗模型资源后才在数据库失败。数据库唯一约束继续保留；不使用 upsert 覆盖同号规则。

结果替换由单独的事务化应用服务执行。删除旧结果和插入全部新结果必须全部成功或全部回滚；插入影响行数不是 1 时立即失败。异步任务重试使用同一套替换逻辑，避免遗留半成品结果。

## 错误处理与兼容性

- 日期无法可靠识别时保留原值并记录格式元数据，不编造日期。
- 重复规则不会再导致任务失败，但在结果 JSON 中保留原始展示编号，便于人工追溯模板质量。
- 已失败记录 119 的部分规则结果在重新执行前清理；重试通过正式任务入口，不直接伪造完成状态。
- 不修改既有数据库唯一键，不新增破坏性迁移。
