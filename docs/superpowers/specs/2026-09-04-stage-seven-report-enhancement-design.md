# 第七阶段：结构化报告、图表与可验证结论设计

日期：2026-09-04

## 目标

在现有报告变量快照、知识库检索、数据库只读查询和 DOCX 渲染链路上，增加结构化表格、柱状图/饼图/趋势图以及基于表格事实的结论，使导出的 Word/PDF 可以直接用于项目风险汇报。

本阶段继续执行 `LOCAL_ONLY`：模型只负责自然语言归纳，不负责计算统计数字；没有证据时不得生成“无风险”“已闭环”等肯定结论。

## 范围

本阶段实现：

1. 把数据库查询结果规范化为有序表格快照，并记录列、行、来源和截断信息。
2. 在 DOCX 中渲染标题、表格、统计摘要和图表。
3. 支持 `BAR`、`PIE`、`LINE` 三种白名单图表。
4. 由确定性程序计算行数、分组数量、占比和日期趋势。
5. 将统计事实交给本地模型生成文字结论，并验证结论中的数字。
6. 模型失败、数字冲突或数据为空时使用确定性结论，不阻断可用报告。
7. DOCX 和 PDF 导出均保留表格、图表和结论。
8. 至少 40 个真实场景实机验收并检查全链路日志。

本阶段不实现拖拽式报告设计器、任意 SQL、任意脚本图表、在线协同编辑或 BI 大屏。

## 基本事实和设计原则

- 数据库结果与知识库证据是报告事实来源。
- 统计必须由程序计算，模型不能成为计算器。
- 报告变量彼此隔离；单变量失败时报告为 `PARTIAL_SUCCESS`。
- 图表配置必须引用真实结果列，类型、聚合方式和最大数据量必须使用白名单。
- 表格空值显示为 `-`，空数据结论为“当前数据源未返回可用于统计的记录”。
- 任何统计数字都必须能从保存的快照重算。
- 表格快照和结论验证结果保存在报告变量结果中，便于下载后审计。
- 项目访问、数据源选择和下载继续复用现有服务端权限校验。

## 组件设计

### 1. StructuredReportTable

Java 将数据库问答的列和行转换为统一对象：

- `columns`: key、label、dataType。
- `rows`: 只包含 columns 白名单中的值。
- `totalRows`: 查询返回总行数。
- `truncated`: 是否超过报告最大展示行数。
- `source`: dataSourceId、queryId、generatedAt。

第一版自动使用查询结果列，不新增复杂模板配置表。对于风险报告，系统通过列名和数据库注释识别风险等级、负责人、日期、描述等语义；识别不到时仍输出原始表格，不猜测字段含义。

### 2. ReportStatistics

确定性统计器支持：

- 总行数和非空行数。
- 文本维度计数，例如风险等级、负责人、状态。
- 日期字段按月计数。
- 数值字段合计。
- 风险等级排序：一级、高、重大优先，其次二级/中，最后三级/低。
- 最多展示前 20 个分组，剩余合并为“其他”。

统计器不调用模型，输入相同必须得到相同输出。

### 3. ReportChartRenderer

Java 使用 JFreeChart 生成 PNG：

- BAR：分类数量。
- PIE：分类占比。
- LINE：按日期或月份趋势。

图表采用固定中文字体探测和无字体降级策略；空数据不生成空白图片，而是在报告中写明原因。图表最大分类数 20，尺寸和分辨率固定，避免 Word/PDF 布局漂移。

### 4. GroundedConclusionService

结论生成分两层：

1. 程序先生成结构化统计事实和标准结论。
2. Python 本地模型可根据事实润色，但不得增加事实字段。
3. Java 提取模型结论中的阿拉伯数字和百分数，与允许数字集合比较。
4. 出现冲突、模型超时或返回为空时使用标准结论，并记录 `fallbackReason`。
5. 无数据时不调用模型。

### 5. DOCX/PDF 渲染

变量渲染顺序固定为：

1. 变量标题。
2. 文字说明。
3. 结构化表格。
4. 图表。
5. “数据结论”段落。
6. 来源和截断提示。

表头重复、金额/数字右对齐、日期统一格式、长文本自动换行。PDF 转换复用现有转换服务；转换失败必须保留可下载 DOCX，并明确状态和错误。

## 数据流

```text
创建报告
  -> 快照变量与数据源
  -> Worker 路由并执行只读查询/知识检索
  -> 规范化结构化表格
  -> 确定性统计
  -> 生成图表
  -> 本地模型润色结论
  -> 数字一致性验证/安全降级
  -> DOCX 渲染
  -> PDF 转换
  -> 保存下载文件和审计信息
```

## 错误处理

- 查询失败：变量失败，其他变量继续。
- 列为空：保存空表快照并生成无数据说明。
- 配置列不存在：拒绝图表并记录可读错误，表格仍可输出。
- 图表生成失败：报告保留表格和结论，变量记录图表错误。
- 模型失败或数字不一致：使用确定性结论。
- PDF 转换失败：DOCX 保持可下载，报告为 `PARTIAL_SUCCESS`。
- 所有重试复用现有上限，禁止无限重试。

## 权限和安全

- 报告、模板、数据源、知识库和下载均校验当前项目。
- 不在日志中输出完整查询结果、个人身份信息或连接凭据。
- 图表和表格只使用已经过结果列白名单处理的数据。
- 数据库仍执行只读 SQL 安全检查和结果行数限制。
- 模型调用保持 `AI_ALLOW_CLOUD_FALLBACK=false`。

## 验收

自动化：

- Java：统计、表格、图表、结论数字校验、DOCX 渲染、失败降级。
- Python：本地结论 Prompt 和结构化响应。
- 前端：报告详情展示表格/图表/结论和状态。
- 全量：Java、Python、前端测试与生产构建。

实机：

- 使用真实 MySQL 项目风险表和真实报告模板。
- 至少 40 个场景，包含空数据、单行、多风险等级、多负责人、日期趋势、金额、长文本、缺失列、查询失败、模型失败降级、DOCX/PDF、权限隔离、刷新恢复和日志审计。
- 每个报告新建独立任务；最终检查 Chrome 控制台、Java、Python、本地 LLM、Embedding、Reranker、MySQL、Redis、MinIO 日志。
- 服务器为双 H100，仅做功能验收；不将其性能作为客户双 A6000 承诺。
