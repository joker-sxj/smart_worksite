# 真实实机验收统一流程

## 适用范围

本流程适用于智慧工地项目所有包含智能能力或跨服务调用的开发阶段，包括问答、文档解析、数据库问答、合规审查、报告生成和 OCR。

## 验收门

1. 规格确认后在隔离分支开发，生产代码使用测试先行方式实现。
2. 每个功能点完成后执行对应基础测试和相关回归；阶段结束时执行 Python、Java、前端全量测试、Python 编译检查和前端生产构建。
3. 自动化测试通过后部署到 Linux，使用真实本地模型、真实入库资料、真实数据库和 Chrome 页面验收。Mock 只能用于隔离单元测试，不能证明业务准确率。
4. 每阶段实机场景不少于 40 个，不设上限。40 个是最低门槛而不是结束条件；场景矩阵未覆盖完整时继续增加，禁止使用同义问题凑数。
5. 每个独立问题先新建会话；只有专门的多轮场景在同一会话连续追问，场景结束后重新新建会话。
6. 分别统计系统执行通过和业务答案通过。HTTP 成功、任务成功或页面出现答案不能自动计为业务通过。
7. 业务通过要求核心事实、数值、日期、主体和条件正确；引用与回答相关；无依据时明确说明。行业常识可以补充，但必须与知识库或数据库证据明确区分。
8. 实机结束后检查 Java、Python、本地模型、Embedding、Reranker、数据库和容器日志。新出现的异常、HTTP 5xx、超时、CUDA OOM、容器重启、无限重试或敏感信息泄漏必须定位、修复并回归。
9. 实机发现缺陷时记录问题、预期、实际结果、消息或任务 ID、时间和日志；先增加最小回归测试，再做通用性修复，不为单题硬编码答案。
10. 每个阶段最多进行一次子智能体代码审查。审查不替代自动化测试、真实实机验收和日志检查。
11. 推送前确认工作区无意外改动、服务器部署提交等于待推送提交、目标远程为 `joker-sxj/smart_worksite`。推送后用 `git ls-remote` 确认远端 `main` 等于验收提交。

## 场景矩阵

每阶段按功能选择并扩展以下类别：正常、边界、空结果、部分证据、无证据、格式变体、长输入、多轮、刷新恢复、并发点击、权限隔离、资源禁用、异步状态、数据库失败、模型失败、检索降级、超时和移动端布局。

## 验收记录

阶段报告至少记录：总场景数、系统执行通过数、业务通过数、失败数、条件通过数、问题、预期要点、实际结论、来源、耗时、消息或任务 ID、判定理由、部署提交和日志检查结论。报告不得保存密码、Token、完整连接串、内部 Prompt 或敏感正文。
