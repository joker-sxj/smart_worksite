## 1. 范围与结论

本项目的本地模型部署是推理与检索增强应用，不是已完成的项目专属训练项目。Java 后端通过 Python AI 服务调用本地模型端点；前端不直接访问模型。`LOCAL_ONLY` 的生产边界、模型 Profile、Docker Compose 和模型健康检查已在仓库中实现，但客户双 RTX A6000 的生产性能验收尚未形成证据。

当前结论：

- 已核验：Profile 中声明的模型 ID、revision、服务名、上下文上限、并发、GPU 选择、镜像 tag/digest 和本地端口。
- 已核验：知识库测试包的文件清单、字节数、SHA-256、公开原件/规范化文本/项目内部测试样本的目录边界。
- `BLOCKED`：各模型 license 的逐项法律核验、客户双 A6000 的 32K/16K 性能和稳定性、项目专属训练或微调制品。
- 已核验的 H100 功能性结果不能替代客户 A6000 的性能结论；现有报告明确禁止这种替代。

## 3. 选择依据与制品核验

可追溯的选择依据是当前系统接口与部署约束，而不是未经测量的性能承诺：

1. 主模型承担对话、报告生成和视觉/文档理解入口；向量模型承担 Embedding；重排序模型承担候选重排。代码和架构文档均要求这些能力通过 Python AI 服务/适配层调用。
2. H100 Profile 与双 A6000 Profile 分开；A6000 提供 32K 目标和 16K 稳定回退，避免把 H100 结果写成 A6000 结论。
3. Profile 固定 revision、服务镜像 digest、GPU 选择、最大上下文和并发，便于复现；启动前还执行 GPU/Container Toolkit、健康检查与 bounded smoke。
4. `QWEN_EMBEDDING_DIMENSIONS=0` 表示使用本地模型原生维度；更换 Embedding 模型或维度时必须重新索引受影响文档。

### 3.1 本地制品完整性基线

H100 已部署缓存的清单位于 `deploy/model-manifests/h100-fp8.json`。它绑定模型 ID、revision、vLLM 镜像 digest、关键运行参数，并记录三类模型快照中每个文件的大小和 SHA-256。启动脚本先在无网络、只读容器中执行全量校验，随后模型容器继续以只读方式挂载缓存；文件缺失、新增或内容变化均阻止启动。

该清单明确标记 `LOCAL_CACHE_BASELINE` 和 `upstreamSignatureVerified=false`。因此它只证明已审查的本地 H100 缓存后来没有变化，不证明上游数字签名、来源真实性、模型授权或法律合规。客户 A6000 使用不同的 BF16 制品，三个 A6000 profile 均保持 `PENDING_CUSTOMER_CACHE`；必须在客户主机预加载最终制品后生成并人工审核各自清单，不能复用 H100 FP8 清单。

### 4.2 可复核完整性

清单 `knowledge_base_package/SOURCE_MANIFEST.md` 的生成日期为 2026-07-29，记录原始清单中的字节数和 SHA-256。复核命令：

`knowledge_base_package` 不在 `smart_worksite` Git 工作树内，是独立交付制品和知识库验收前置条件。交付方必须先提供该目录及版本/来源说明；目录缺失或 manifest 无法核验时，知识库/RAG 验收为 `BLOCKED`，不能用临时文件、Mock 或替代样本补齐。

```bash
cd "$(git rev-parse --show-toplevel)/../knowledge_base_package"
awk -F'|' 'NR > 7 && $2 ~ /./ {gsub(/^[[:space:]]+|[[:space:]]+$/, "", $2); gsub(/^[[:space:]]+|[[:space:]]+$/, "", $3); gsub(/^[[:space:]]+|[[:space:]]+$/, "", $4); gsub(/^[[:space:]]+|[[:space:]]+$/, "", $5); print $2 "/" $3 "\t" $4 "\t" $5}' SOURCE_MANIFEST.md |
while IFS=$'\t' read -r file bytes expected; do
  test "$(wc -c < "$file" | tr -d ' ')" = "$bytes" || { echo "SIZE_MISMATCH $file"; exit 1; }
  test "$(sha256sum "$file" | cut -d' ' -f1)" = "$expected" || { echo "SHA256_MISMATCH $file"; exit 1; }
done
```

### 4.3 清洗、切分、索引与保留

- 离线测试包的抽取脚本 `knowledge_base_package/scripts/extract_official_text.py` 使用 `pypdf` 抽取 PDF、`HTMLParser` 抽取 HTML、`python-docx` 抽取 DOCX；清洗包括 HTML 实体还原、全角/不换行空格替换、行内空白归一化、空行压缩和少量导航文字过滤。该脚本不提供授权判断、语义去重或敏感信息脱敏。
- Java 负责文件类型识别、解析任务和解析结果持久化；Python RAG 服务对文本执行空白归一化后按 `chunk_size` 与 `chunk_overlap` 切分。默认值应以运行时配置为准，不在本文猜测具体数值。
- RAG chunk ID 由项目、知识库、文档、块位置和内容的 SHA-256 派生；索引替换前先准备文档块，失败不应先删除原有文档块。这些行为可在 `python-ai-service/app/services/rag_service.py` 核验。
- 向量检索必须带项目/知识库范围；业务层还要校验项目成员、知识库类型和启用状态。不得用检索降级绕过权限隔离。
- 去重目前至少有文件解析层的活动解析唯一性迁移（`V21__enforce_active_file_parse_uniqueness.sql`）和 RAG chunk 的稳定 ID；不能据此声称完成跨来源语义去重。
- 原始文件、解析结果、索引块和业务元数据分层保存；仓库未形成统一模型数据自动删除/保留周期的完整证据，具体保留天数以项目配置和客户政策为准，**BLOCKED** 的保留审批不能省略。
- 脱敏不是自动推定已完成的步骤。身份证、手机号、银行卡和客户文档必须按授权范围、最小化使用、日志不落明文执行；没有字段级脱敏验收证据时，交付文档只能标为人工复核/`BLOCKED`。

## 5. 训练、提示词、RAG 与工具调用边界

| 能力 | 当前边界 | 是否等同训练 |
|---|---|---|
| 基础模型 | 使用 Profile 指定的本地权重 revision | 否 |
| Prompt/结构化输出 | Python AI 服务负责请求约束、响应解析和错误映射 | 否；Prompt 版本需随调用证据记录 |
| RAG | 对已授权项目/政策文档切分、Embedding、检索、重排并返回来源 | 否；RAG 不改变基础模型权重 |
| 工具调用 | 通过受限的数据库只读查询、任务/业务适配层获取证据；执行前做权限和安全校验 | 否 |
| 确定性规则 | 项目隔离、状态机、SQL 安全校验、字段规范化、边界/拒答约束 | 否 |
| fine-tuning/LoRA/继续预训练 | 当前未发现项目专属训练脚本、训练配置、训练数据集、训练日志或产出权重 | **当前没有项目专属训练或微调证据，不声明已训练** |

如后续要进行训练，必须新增数据授权、数据集版本与 checksum、训练配置、基础模型 revision、训练日志、产出权重 checksum、license/发布边界、回滚方案和独立评测报告；在这些证据齐全前，生产路径保持“基础模型 + Prompt + RAG + 受限工具 + 确定性规则”。
